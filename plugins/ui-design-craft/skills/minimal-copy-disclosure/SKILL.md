# Minimal 文案与按需披露：把"用户给的"炼成"用户要看的"

AI 文案病的根因：把提示词/PRD 里的卖点**照搬**成副标题和说明段。人类设计朝 minimal 走——不是没有信息，而是信息分层：首屏一句主张，说明藏起来等触发。本套管**文字与信息**；功能控件（按钮/工具栏/面板）的披露见 frontend-ui-ux 第 3 节。

## 0. 三个事实先验（所有规则的出处）

1. **扫读不是阅读**：视线只落标题、段首、加粗、数字、链接（F 型/层蛋糕模式）。段落越长，被读的概率越低——长说明段基本等于没写。
2. **注意力税**：每一条可见文字都在向所有访客收税；藏起来的文字成本 ≈ 0。默认态露出的每个字都要能回答"删掉会怎样"。
3. **触发才出现是设计精华**：tooltip、折叠、"更多"——按需呈现让扫读的人不被打扰、想要的人点一下就有。但**触发器本身必须可见**：藏 ≠ 消失，藏 = 有形状的线索。

## 1. 卖点提炼：炼到消失为止

- **照搬禁令**：提示词/PRD/会议纪要里的卖点句，禁直接变副标题。副标题是一句主张（≤ 12 字），不是一段解释。
- **炼化方向只许单向**：一段话 → 一句话 → 短语 → 数字。能量化就量化（"极快" → "80ms 首屏"）；数字与具体名词是唯一的扫描锚点，形容词不是。
- **一屏一主张**：主标题一句 + 至多一个副句 + 一个主 CTA + 一个视觉证据（图/数据）。就这些，别的全是税。
- **三卖点不是法律**：提示词给 5 个卖点不等于页面出现 5 块。合并到 ≤ 3，能立住 1 个就不用 3 个。落选的不是丢了，是按第 2 节档位下沉。
- **自检**：首屏文案读出声超过 30 秒 = 堆了，回炉。

## 2. 说明文字五档（默认态只许 0–1 档）

写任何说明句之前，先问**能不能降一档**：

| 档 | 形态 | 装什么 |
| --- | --- | --- |
| 0 | 不写 | 显而易见的：按钮写着"下载"，旁边不用再写"点击下载" |
| 1 | 一行占位/示例 | 输入框 placeholder、表单 hint |
| 2 | 触发显示 | tooltip / hover / 聚焦提示，挂在 ? 图标或虚线下划线上 |
| 3 | 点击展开 | 折叠面板、抽屉、"了解更多" |
| 4 | 独立页 | 完整文档、帮助中心 |

- 落选卖点、字段解释、风险提示、版本说明……全部按档位沉，默认态一个都不许留成段落。
- **触发器密度也克制**：通篇下划线等于没有下划线；一屏触发式线索 ≤ 3 处。
- 空态、首屏、报错信息里禁成段介绍文字——这三处用户本来就慌或没耐心。

## 3. 浏览习惯 → 排版推论

- **关键词前置**：信息词放标题和段首，禁"我们提供……"、"致力于……"开头——前 4 个字是视线唯一承诺停留的地方。
- 段落 ≤ 3 行；连续段落 > 3 段必须拆小标题（层蛋糕：密集的小标题比一篇长文好扫十倍）。
- **首屏最贵，底部宽容**：页面越往下信息密度可以越高——滚到底的是高意图用户。倒过来排（首屏塞满、底下空）是最常见的浪费。
- 中文界面文案短句优先，一句一意；长句拆句不算增加字数，算增加锚点。

## 4. 红线速查（出现即打回）

- 副标题复读主标题（"更快 · 让你的工作更快"）
- 默认态同屏完整说明句（> 10 字的陈述句）超过 2 句
- icon + 标题 + 两三行小字说明的卡片连排 ≥ 3 组——这是 AI 生成页的标准脸
- 形容词卖点：强大 / 领先 / 一站式 / 赋能 / 极致（无信息量，删掉或换数字）
- 功能名后跟括号解释（沉到 tooltip）
- 首屏 CTA 超过 1 个强调色的

## 5. 验证（挂接 frontend-ui-ux 第 5 节的截图闭环）

截图后加做三条：

1. **删字测试**：逐块遮住文字，遮住后页面主张不变的，就是该删或该沉的。
2. **5 秒三问**（只看首屏截图）：这是什么 / 对我有什么用 / 下一步做什么。答不出任一 = 首屏失败。
3. **数说明句**：默认态截图里 > 10 字的陈述句超过 2 句 = 打回。
